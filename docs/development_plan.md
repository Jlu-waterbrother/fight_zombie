# 向僵尸开炮（像素风）开发步骤

## 目标定义
- 玩法核心：玩家固定在屏幕下方，持续击杀自上而下的敌人。
- 成长循环：击杀敌人获得经验，升级后在“新武器/强化已有武器”中二选一。
- 胜负条件：
  - 敌人接近玩家并造成伤害，玩家生命归零则失败。
  - 清空本关所有敌人则胜利。
- 风格目标：像素风（美术与特效后续逐步替换，不阻塞核心玩法开发）。

## 开发阶段总览
1. 阶段 0：项目骨架与运行主流程
2. 阶段 1：玩家、生存与失败条件
3. 阶段 2：敌人生成、移动与基础击杀
4. 阶段 3：经验与升级选择系统
5. 阶段 4：武器系统（新武器 + 强化）
6. 阶段 5：关卡波次、胜利判定与结算
7. 阶段 6：像素风表现层（UI/特效/音频）
8. 阶段 7：平衡、存档与发布前验收

## 阶段 0：项目骨架与运行主流程
**阶段目标**
- 保证 `bootstrap -> main_menu -> run_game` 流程稳定。
- 统一运行时服务入口（autoload）与最小 HUD 框架。

**主要产出**
- `scenes/run_game.tscn` 能稳定加载核心节点（玩家容器、敌人容器、UI 容器）。
- `autoload/game_state.gd` 增加 run 生命周期接口（开始/结束/重置）。

**完成标准**
- 可从主菜单进入战斗并返回。
- 无脚本报错、无空引用。

**需要你在 Godot 验证**
- 打开并运行主场景，确认场景切换链路正常。
- 检查 Remote SceneTree，确认运行时节点结构符合预期。

---

## 阶段 1：玩家、生存与失败条件
**阶段目标**
- 落地玩家固定站位、生命值、受伤与死亡失败逻辑。

**主要产出**
- 玩家节点固定在屏幕下方，不参与自由移动。
- 玩家生命组件（复用 `core/components/health_component.gd`）接入 HUD。
- 玩家死亡触发失败流程（暂停战斗、弹出失败界面）。

**完成标准**
- 敌人接触玩家时会掉血。
- 生命归零后进入失败，不再继续生成敌人或结算经验。

**需要你在 Godot 验证**
- 手动让敌人接近玩家，确认伤害触发频率与失败切换。
- 检查 HUD 的血量展示是否实时更新。

---

## 阶段 2：敌人生成、移动与基础击杀
**阶段目标**
- 敌人从屏幕上方生成并朝玩家方向推进，支持被击杀与回收。

**主要产出**
- 波次/刷怪基础调度（可先定时刷）。
- 敌人 AI（向下或朝玩家位置推进）。
- 敌人死亡事件接入 `autoload/event_bus.gd`。

**完成标准**
- 敌人持续生成并进入战场。
- 敌人可被命中并死亡，死亡后不会残留碰撞体。

**需要你在 Godot 验证**
- 观察 3~5 分钟运行，确认无明显卡顿/节点泄漏。
- 打开 Debug 可视化，确认碰撞层与命中区域正确。

---

## 阶段 3：经验与升级选择系统
**阶段目标**
- 完成“击杀 -> 经验 -> 升级 -> 选择奖励”的核心成长闭环。

**主要产出**
- 经验条与等级数据模型（当前经验、升级阈值、等级）。
- 升级暂停层：每次升级展示若干选项。
- 选项类型先实现两类：新增武器、强化已有武器。

**完成标准**
- 连续升级时逻辑稳定，不丢失经验。
- 选择奖励后立即生效并恢复战斗。

**需要你在 Godot 验证**
- 使用高经验倍率快速连升，检查多次升级是否正确。
- 反复打开升级界面，确认输入焦点与暂停状态无异常。

---

## 阶段 4：武器系统（新武器 + 强化）
**阶段目标**
- 建立武器运行时框架：武器可新增、可升级、可配置。

**主要产出**
- 武器基类与运行时实例管理（参考 `game/weapons/scripts/`）。
- 至少 2~3 把武器实现（示例：单发枪、散射、持续伤害）。
- 强化维度（伤害/射速/穿透/范围）数据化配置。

**完成标准**
- 升级后武器表现可观测变化。
- 武器数量增加时不需改核心流程代码（数据驱动优先）。

**需要你在 Godot 验证**
- 对比升级前后 DPS 体感和目标清理效率。
- 验证不同武器同时存在时的性能与特效叠加。

---

## 阶段 5：关卡波次、胜利判定与结算
**阶段目标**
- 从“无限刷怪”过渡到“可通关波次”，实现胜利和结算。

**主要产出**
- 波次配置（敌人种类、数量、间隔、精英）。
- 胜利条件：所有波次结束且场上无存活敌人。
- 结算界面：显示击杀数、存活时间、等级、获得奖励。

**完成标准**
- 失败与胜利互斥，状态切换唯一且可复现。
- 结算后可返回主菜单并再次开局。

**需要你在 Godot 验证**
- 分别手动触发胜利与失败，确认流程分支正确。
- 连续开局 5 次，确认状态会完整重置。

---

## 阶段 6：像素风表现层（UI/特效/音频）
**阶段目标**
- 在不改核心逻辑前提下统一像素风呈现。

**主要产出**
- 像素风 UI 主题与字体（`game/ui/themes/`、`assets/fonts/`）。
- 命中反馈、受击闪烁、死亡特效与关键音效。
- 主要界面（主菜单/HUD/升级/结算）视觉一致性。

**完成标准**
- 核心反馈（命中、升级、受伤、死亡）清晰可辨。
- 美术资源替换不影响玩法逻辑层。

**需要你在 Godot 验证**
- 多分辨率下检查 UI 对齐和可读性。
- 实机听感检查 BGM/SFX 的音量平衡与重叠表现。

---

## 阶段 7：平衡、存档与发布前验收
**阶段目标**
- 做到可持续游玩、数值合理、流程稳定可发布试玩。

**主要产出**
- 数值调优：敌人强度曲线、经验曲线、武器成长曲线。
- 存档策略：基础设置与进度（`autoload/save_service.gd`）。
- 发布前清单：性能、崩溃、输入、分辨率、音频、文案。

**完成标准**
- 新手可上手，10~20 分钟内完成一次完整体验。
- 无阻断级 bug（卡死、无法结算、无法开局）。

**需要你在 Godot 验证**
- 至少 3 次完整通关/失败回合，记录关键问题。
- 使用 headless 命令做基础加载校验：`godot4 --headless --path . --quit`。

## 协作执行方式（你和我）
- 你每次指定“当前阶段 + 子目标”，我按该子目标做最小可运行改动。
- 我每次提交改动后，会给你：
  1) 本次改动清单；
  2) 你需要在 Godot 里执行的验证步骤；
  3) 通过/失败后的下一步分支建议。
- 你在本地做的手动修改我会视为最新基线，在其上继续迭代。
